## Исполняемые компоненты

| Компонент | Назначение | Запуск | Режим |
|---|---|---|---|
| `api-server` | REST API, HTML-шаблоны, HTMX partials, статика и фото | Docker local/prod | Долгоживущий production-сервис |
| `mqtt-consumer` | Получение телеметрии EcoWitt из MQTT и запись измерений | Docker local/prod | Долгоживущий production-сервис |
| `migrator` | Применение SQL-миграций Goose | Docker prod; вручную через CLI/Makefile | Одноразовый startup job |
| `forecast-fetcher` | Загрузка прогноза Open-Meteo в PostgreSQL | Docker prod | Фоновый production-сервис |
| `narodmon-sender` | Отправка последних измерений в Narodmon | Docker prod | Фоновый production-сервис |
| `geomagnetic-fetcher` | Загрузка геомагнитного прогноза XRAS | Docker local/prod | Фоновый production-сервис |
| `hydro-fetcher` | Загрузка уровней воды из источника МЧС | Docker local/prod | Фоновый production-сервис |
| `telegram-bot` | Команды, фото, подписки, погодные уведомления и сводки Telegram | Docker local/prod | Долгоживущий production-сервис |
| `max-bot` | Команды, подписки, погодные уведомления и сводки Max | Docker local/prod | Долгоживущий production-сервис |
| `weather-tui` | Терминальный клиент, читающий данные через REST API | Ручной запуск | Локальный CLI; не входит в Docker image |

Все десять каталогов `cmd/*` перечислены в таблице. Dockerfile собирает девять серверных бинарников; `weather-tui` собирается и запускается отдельно.

## Основные архитектурные решения

- Один Go-репозиторий содержит несколько небольших процессов с общей доменной моделью и repository/service слоями.
- PostgreSQL с расширением TimescaleDB — общий источник истины для телеметрии, прогнозов, подписок и обогащающих данных.
- Веб-интерфейс рендерится на сервере Go templates и обновляет фрагменты через HTMX.
- Фоновые интеграции изолированы в отдельных процессах: отказ внешнего источника не должен останавливать HTTP serving или MQTT ingestion.
- Telegram и Max используют отдельные таблицы пользователей, подписок и дедупликации уведомлений.
- SQL-миграции применяются отдельным `migrator` до запуска production-сервисов.

## Границы комплекта

Здесь нет:

- построчного справочника HTTP endpoints;
- полного перечня переменных окружения и их значений;
- копии SQL schema и описания каждого столбца;
- продуктового roadmap;
- реальных секретов, токенов и production URL.

Такие детали читаются из handler-кода, `.env.example`, `internal/config/config.go` и миграций. Архитектурный комплект фиксирует границы, ответственность и взаимодействия.

## Правило актуализации

Документацию нужно пересматривать в том же изменении, которое:

- добавляет, удаляет или переименовывает каталог `cmd/*`;
- меняет `Dockerfile` или любой Compose-файл;
- добавляет миграцию или новый домен данных;
- добавляет внешний API, broker, bot channel или persistent volume;
- меняет направление зависимости между handler, service и repository слоями;
- меняет startup order, healthcheck или процедуру восстановления.
